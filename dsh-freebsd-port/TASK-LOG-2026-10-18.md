## 4. 踩坑与修复（按主题）

### 4.1 distfile 不可移植：workspace 包是"指向源码仓库的符号链接"

**现象**：在 1.5 上 `make install` 后跑 `dsh --help`，报
`ERR_MODULE_NOT_FOUND: @deepseek-ai/cosmokit`（以及一堆 `@deepseek-ai/*` 找不到）。

**根因**：`pnpm deploy --legacy` 把 workspace 包（`@deepseek-ai/*`）以**符号链接**形式放进 deploy 树，
链接目标是构建机源码仓库的绝对路径，例如
`node_modules/@deepseek-ai/cosmokit -> ../../../../github/deepseek-harness/vendor/...`。
这套闭包在 1.5 本机能解析，但 distfile 拷到别的机器（或校验用的 `/tmp/dshtest`）后链接**悬空**，
于是运行时按名 `require` 找不到 → 启动即崩。

**修复**：在 `make-port-distfile.sh` 的 `reconcile` 之后、`tar` 之前，新增"解引用"步骤：
扫描 `node_modules` 下所有指向 `*github/deepseek-harness*` 的符号链接，删链接、把目标**真实复制**成副本。

```sh
log "fixups: dereference source-pointing symlinks (make the bundle portable)"
cd "${STAGE}" || die "cd ${STAGE} failed"
find node_modules -type l 2>/dev/null | while read -r l; do
  tgt=$(readlink "$l" 2>/dev/null || true)
  case "$tgt" in
    *github/deepseek-harness*)
      real=$(readlink -f "$l" 2>/dev/null || true)
      if [ -n "$real" ] && [ -e "$real" ]; then
        rm -f "$l"; cp -R "$real" "$l"
      fi ;;
  esac
done
echo "  source symlinks remaining: $(find node_modules -type l 2>/dev/null | xargs -I{} readlink {} 2>/dev/null | grep -c github/deepseek-harness)"
```

**验证**：重跑管线后 `source symlinks remaining: 0`，生成的 distfile（62,207,174 B）在 1.5 上 `make install` + `dsh --help` 全绿。

### 4.2 pnpm deploy 闭包漂移 / `cordis-plugin-group` 缺失

**现象**：各种 `pnpm deploy` 组合都漏装 `cordis-plugin-group`（cordis 动态加载的插件组），因为
`dsh-app-boot` 把它声明为 **peerDependencies**，而 `pnpm deploy --prod` 只装静态 `dependencies`。
不补齐就 `ERR_MODULE_NOT_FOUND`。

**修复（已固化在脚本）**：内嵌 `reconcile.mjs` 从**源码目录**（`packages/vendor/apps/...`，排除 `node_modules/.git`）
按 package.json name 扫出所有 `@deepseek-ai/*`，把 deploy 树里缺失的补复制进来。
**关键**：绝不从 `node_modules` 拷贝 —— 那边有上游删除遗留的悬空 symlink（`cp` 报 ENOENT）和 symlink 环（`cp -RL` 报 cycle 并拷出 20 层嵌套）。

### 4.3 pkg-plist 的两个坑

1. **`#` 注释行**：`pkg-plist` 里手写的 `# comment` 行 `check-plist` 不认，直接报错 → 删掉。
2. **手动 `@stopdaemon dsh_web` 行**：本以为是必需，实际 `USE_RC_SUBR=dsh_web` 框架会**自动注入** `@stopdaemon` 关键字，手写反而重复。删掉手动行后 `check-plist` 干净通过。

### 4.4 `stopdaemon` 关键字在本机 ports 树缺失（测试环境模拟）

**现象**：`make install` 在 1.5 上偶发 `pkg-static: unknown keyword stopdaemon`。

**根因**：本机 `/usr/ports/Keywords/stopdaemon.ucl` 缺失。正式 ports 树随框架自带此文件；
这里是测试环境，需补。

**测试环境补丁**（仅本机，不进仓库）：
```ucl
# /usr/ports/Keywords/stopdaemon.ucl
post-install: <<EOS
  if [ -x /usr/sbin/service ]; then
    /usr/sbin/service %@ onestop >/dev/null 2>&1 || true
  fi
EOS
```
**注意**：原版若带 `actions: [file, dir]`，pkg 会把参数（`dsh_web`）当**文件路径**去 stat，
报 `work/stage/tmp/dshtest/dsh_web/` 不存在 → 失败。去掉 `actions`、只留 `post-install` 按名字停服务即可。
（真实 ports 树里的 `stopdaemon.ucl` 已经是正确的形态，无需改动。）

### 4.5 `make install` 非 root → `su: Sorry`

ports 惯例 `make install` 会切 root。本机普通用户直接跑会失败。**必须用 `ssh_run.py --sudo`**
（脚本内部 `sudo -S`）在远端以 root 执行 install。

### 4.6 4.8 MB heredoc 安装脚本 SSH 传输超时

早期尝试把整个 port 目录（含 4.8 MB `pkg-plist`）内联进一个 `install-port-files.sh` heredoc，
用 `ssh_run.py --file` 上传执行 —— paramiko 通道在 4.8 MB 脚本上 **PipeTimeout** 超时。

**修复**：改用 `tools/port_push.py`，用 `sftp.put()` 直传 7 个真实 port 文件；目录创建走
SSH `exec_command("mkdir -p")`（本机 SFTP `mkdir` 报 Failure，shell 建目录稳）。
→ **`install-port-files.sh`（4.8 MB）是过时传输产物，已不进仓库**，由 `port_push.py` 取代。

### 4.7 其它已固化的小坑（详见 `PORTING.md` §2）

- **stage 必须与 pnpm store 同文件系统**（否则 pnpm 静默改 `/tmp/.pnpm-store` 联网重下 → npmmirror 超时卡死）。`DSH_WORK` 默认放 home 下。
- **`pnpm deploy` 必须 `--legacy`**（pnpm 11 默认实现遇 shared lockfile + allowBuilds 失配直接失败）。
- **`uarch` 文件标志**：pnpm store 的硬链带 `uarch` flag，`rm -rf` 报 EPERM；清理前先 `chflags -R 0`。对 distfile 无影响（tar 不存 fflags）。
- **冒烟必须 detached + 自记录日志**：SSH 通道一断前台脚本被 SIGPIPE 杀；脚本内 node 重定向已隔离，外层再 `nohup` 自脱离。
- **不要在仓库构建进行中跑产包脚本**：`clean` 窗口期 `lib/` 短暂消失，预检直接 FATAL。先 `pgrep -fl 'tsc -b|pnpm run build'` 确认空闲。
